# デザインシステム（v8 リブランディング）

Claude Design で決定した方向性を実装に落とし込んだもの。
トーンは「カジュアル寄り」から「クリーンでテック感のある落ち着いたブログ」へ。
ブランドカラーのオレンジは維持する。

実体は `assets/styles/_tokens.scss`（値）と `assets/styles/_mixins.scss`（見出し・組版）。
**このドキュメントとSCSSトークンが常に一致している状態を保つこと。**

## タイポグラフィ

- 見出し・ロゴ・ナビゲーション・ラベル/メタ情報：**Zen Maru Gothic**（500 / 700）
- 本文：**Zen Kaku Gothic New**（400 / 500 / 700 / 900）。地の文（`html`基準）はweight 500を標準とし、Regular(400)よりわずかに強めの太さで可読性を確保する
- CMS本文中の `<code>` のみ：**JetBrains Mono**（500 / 700）

いずれも Google Fonts（無料）。読み込みは `nuxt.config.ts` の `app.head.link` で行う。

**JetBrains Monoはナビゲーション・ラベル・バッジ等のUIチロームには使わない。** 初期実装ではモノスペースで
統一していたが、和文との相性・可読性の観点からUI文字は全てZen Maru Gothicに統一した。残るのは記事本文
（CMS）中の `<code>` インライン要素のみで、これは意図的な例外（コード表記の慣習に合わせるため）。

日付・パンくず・タグ・eyebrowラベルなど「読ませる短いテキスト」は `@include label($color)` で
Zen Maru Gothic 500 / 15px に統一する（ヘッダーナビと同じ扱い）。ただしカード内の日付・関連記事の
タグチップ・ページネーションの数字・フッターの著作権表記など、絶対的なスペースが小さいUI部品は
`label` mixinを使いつつ `font-size` を12〜14px程度に個別調整してよい（`components/ArticleCard.vue`
の `.card__date` / `.card__tag` 参照）。

## 見出しシステム

サイト全体で最も重要なデザイントークン。mixin として実装済み（`@include heading-1` など）。
CMS本文（v-html）の `h2` / `h3` / `h4` にも `@include article-typography` 経由で同じ規則が適用される。

**注意：見た目の優先度とHTMLタグ番号は一致しない。** 実際のCMSコンテンツ（microCMSのリッチエディタ）では
記事本文の大見出しに `h3`、小見出しに `h4` が使われ、`h2` はほぼ使われない（ページ本体の `h1` は
記事タイトル側で別に出力されるため）。この実態に合わせて、視覚的な優先度は
**H1（全幅下線） > H3（全幅下線・実質の大見出し） > H2/H4（丸ドット）** としている。
mixin名と`<h2>`〜`<h4>`タグの対応自体は変えず、CSSの中身だけをこの優先度に合わせて割り当てている
（`assets/styles/_mixins.scss` 参照）。H2とH4は当初のモック案でH3に使われていた丸ドットデザインを
共有する（H2はCMS本文でほぼ未使用、H4はCMS本文の小見出みとして実際に使われる）。

| レベル | HTMLタグ                               | 用途                     | 指定                                                                                                                                                                                                      |
| ------ | -------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1     | `<h1>`（記事タイトル・ページタイトル） | ページの主見出し         | Zen Maru Gothic Bold `clamp(24px, 4vw, 32px)`、直下に**横幅いっぱい**のオレンジ下線バー（高さ4px・角丸2px）。**ページ内で1つだけ**                                                                        |
| —      | `<h3>`（CMS本文の実質的な大見出し）    | セクションの区切り       | Zen Maru Gothic Bold 23px、直下に**横幅いっぱい**のオレンジ下線（高さ3px）。H1と同じ全幅下線モチーフ（太さのみ4px→3pxで一段控えめ）。CMS本文中では上に1pxの罫線＋64pxの余白も加えセクションの切れ目を明示 |
| —      | `<h2>`（CMS本文ではほぼ未使用）        | 補助的な区切り           | Zen Maru Gothic Bold 16px、左に 7px 円のオレンジドット。ただしこの対応はCMS本文（`article-typography`）限定で、`pages/index.vue`の「記事一覧」は`<h2>`タグのまま`heading-3`の見た目（下線）を使う         |
| —      | `<h4>`（CMS本文の小見出し）            | 補足・キャプション見出し | H2と同一（Zen Maru Gothic Bold 16px、左に7px円のオレンジドット）。背景chip化・下線はどちらも使わない（リストが連続する箇所で見出しが浮くのを避けるため。下線はH3との混同回避）                            |

見出し前後の余白は「区切りの分かりやすさ」を優先し、H2は上44px（下は`heading-2`の14px）、
H3は上64px＋上に1pxの罫線＋`padding-top: 32px`（下は`heading-3`の20px）を確保する
（`assets/styles/_mixins.scss` の `article-typography` 参照）。

ページのUI見出し（`pages/index.vue`の「記事一覧」など）は文書構造を優先してタグを決め、
見た目はmixinで別途指定する。「タグとmixin名を一致させる」原則はCMS本文（`article-typography`）内の話。
記事詳細では h1（記事タイトル）の下にCMS本文のh3が来るため見出しレベルが飛ぶが、これはCMS側の
既存データがh3/h4主体であることによる制約で、コード側では解消しない。

## 角丸

- カード全体：14px（`$radius-card`）
- 画像（大）：12px（`$radius-image`）
- 画像（小・グリッド内）：10px（`$radius-image-sm`）
- バッジ / pill / ページネーション丸ボタン：20px または 50%（`$radius-pill`）
- アクセントバー：2px（`$radius-bar`）

## 余白

- カード内パディング：24px 前後を基本単位（`$space-card`）
- 記事グリッドの gap：16px（`$space-grid`）
- セクション間の区切り：1〜2px の罫線＋18〜32px の余白

## 画面

### ヘッダー（全ページ共通・fixed / 高さ56px）

ヘッダー本体（`.header`）は常に透明。左＝ロゴタイプ（ロゴマーク＋「がじぇっとぐらし！」）、
右＝`HOME` / `ABOUT`（Zen Maru Gothic 500, 15px）を、それぞれ独立した高さ36px・`$color-header-bg`
塗りのピルとして重ねる（`$radius-pill`）。2つのピルの高さは必ず揃える（`height`指定＋`padding: 0 __px`。
片方だけ縦paddingで高さを決めると誤差でズレるため）。
現在のページのリンクはオレンジ＋bold＋下に2pxのアクティブバー、非アクティブは `$color-nav-inactive`。

フッターのHOME/ABOUTも同じ書体・サイズで統一。フッター本体（`.footer`）もヘッダーと同じく常に
透明で、ロゴ（`.footer__brand`）・ナビ（`.footer__nav`）・著作権表記（`.footer__copyright`）を
それぞれ独立した`$color-header-bg`のピルとして塗る（ヘッダーのピルと完全に同じ色・同じ目的＝
背景パターンを隠すこと）。
フッターの「PAGE TOP」ボタンと、固定スクロールボタン（旧`components/NavButton.vue`）は
どちらも廃止した。前者はページ最下部で両者が並んで表示されて機能が重複していたため、
後者もその後の見直しで不要と判断した。トップに戻る手段は現状ブラウザ標準の操作に委ねる。
フッターの上端の区切り線（旧`border-top`）も、本体が透明になったことで不要になり撤去した。

**重ね順（z軸）の原則：「ヘッダー／フッターのピル > コンテンツ > 背景色 > 背景パターン」。**
ヘッダー・フッター本体に不透明な塗りを持たせない理由はこれで、もし本体ごと塗ってしまうと
（`position: fixed`でz-indexが高いため）スクロールしてきたページのコンテンツより手前に
その塗りが乗ってしまい、上記の重ね順が崩れる。ピル部分だけが常に最前面で良い
（ヘッダーは常時fixed、フッターはページ末尾だが、どちらも「パターンを隠す」目的は同じ）。

### トップページ（`pages/index.vue` / `layouts/home.vue`）

1. ヒーロー画像（角丸12px、`clamp(180px, 32vw, 360px)`）。幅は`$content-width`が基本だが、
   PCの2カラム表示（`$bp-lg`以上、サイドバーが横に並ぶ）ではサイドバーを含めた行全体の幅
   （`$container-width`）まで伸ばす。イントロブロック・記事一覧は常に`$content-width`のままなので、
   SP/タブレットではヒーローもそれらと同じ幅に揃い、PCでのみヒーローだけが行幅いっぱいに広がる
2. イントロブロック：eyebrowラベル「WELCOME」（Zen Maru Gothic Bold／オレンジ）＋ H1 ＋ 本文 ＋「このブログについて →」
3. 記事一覧セクション（`<h2>`、`@include heading-3`）：先頭記事を「注目」バッジ付きの1カラム大カード、以降は2カラムグリッド
4. ページネーション：丸ボタン。現在ページはオレンジ塗り、他はグレー

記事詳細・about・記事一覧ページ（`layouts/default.vue`）は独自の「ヒーロー」band を持たず、
`.contents__main`がそのまま`$content-width`なので、トップページのイントロ／記事一覧と
同じ幅で揃っている（確認済み。ズレていそうに見える場合は大抵ブラウザキャッシュか、
このヒーローのようにPCでのみ意図的に広げているブロックとの比較）。

### 記事一覧（`pages/page/[p].vue` / `pages/tag/[tagId]/page/[p].vue`）

パンくず（Zen Maru Gothic 15px）＋ H1 ＋ 件数などのメタ ＋ 2カラムグリッド ＋ ページネーション。

### 記事詳細（`pages/article/[id].vue`）

パンくず「← TOP」（`components/Breadcrumb.vue`。カテゴリバッジは廃止済み）→ アイキャッチ（角丸12px・バッジなし）→ H1＋オレンジ下線バー →
メタ情報（日付・更新日・読了◯分）→ 本文 → タグ → 関連商品リンク → 2pxの区切り線 → 「シェアする →」（右寄せ・ブルー）→
RELATED（ラベル＋2カラムのサムネイル付き関連記事。各カードにタグも表示する）。

背景パターンとの関係では、この一連の流れは3つのブロックに分かれる：
①パンくず〜タグ（本文の読み物としてのまとまり）、②関連商品リンク（`@include card`の白カード。
それ自体が独立した見た目のため単独でパターンの上に浮かせる）、③区切り線〜シェア〜広告。
RELATEDはさらにその下で独立したブロック。詳しくは「背景パターン」の節を参照。

## カードとバッジのルール

- 記事カードは画像・タイトル・日付のみ。**背景の色塗りやドロップシャドウは使わない**
- バッジは必ず画像に重ねる（pill形状）。注目＝オレンジ、カテゴリ＝ブルー
- hover は画像のわずかな拡大とタイトルのオレンジ化のみ

## 背景パターン

ページ全体の背景に、ガジェットモチーフ（スマホ・ヘッドホン・スマートウォッチ・Wi-Fiルーター・
マグカップ・電球の6種）を薄い線画で並べた装飾パターンを敷く。実体は `components/BackgroundPattern.vue`。

- SVGの`<pattern>`に`patternTransform="rotate(30)"`を適用してグリッド全体を30°回転させ、
  各アイコンには個別に`rotate(-30)`をかけて相殺する（アイコン自体は常に正立を維持）
- タイルは144×216px（2列×3行）、アイコンは`#c7cfd9`の線幅2px相当、継ぎ目なく反復
- `layouts/home.vue`と`layouts/default.vue`の`.layout`直下・最初の子要素として配置し、
  ページ全体の背景に1枚だけ敷く。`.layout`には`position: relative; z-index: 0;`を必須で付け、
  スタッキングコンテキストを作ってパターン(`z-index: -1`)をその中に閉じ込めること
  （**これを忘れるとパターンがbodyの背景の下に潜り込んで完全に不可視になる**）
- `BackgroundPattern`自体は`position: fixed; inset: 0;`でビューポートに固定し、スクロールしても
  動かない（コンテンツだけがその上をスクロールする）
- コンテンツは「行」ごとではなく**まとまり単位**（ヘッダー／フッターの各ピル・イントロブロック・
  区切り線・記事一覧の見出し・各記事カード・ページネーション・記事詳細ページ全体・aboutページ全体・
  サイドバーのSPONSOREDなど）でブロックとして塗る。まとまり同士の余白部分ではパターンを見せる
- 塗りは完全な不透明ではなく `@include content-block($color: $color-bg, $opacity: 0.95)`
  （`assets/styles/_mixins.scss`）を使う。`rgba($color, 0.95)` + `backdrop-filter: blur(10px)`で、
  パターンがうっすら透けるすりガラス調にする。色を変えたいブロック（ヘッダー／フッターの
  各ピルは`$color-header-bg`）は`content-block($color)`で指定する。サイドバーは独自の色を
  足さずデフォルトの`$color-bg`のまま使う（詳細は「ヘッダー」の節を参照）
- aboutページ（`pages/article/about.vue`）は一連の読み物なので、ページ全体をひとつの
  `content-block`（`.about`）として塗る
- 記事詳細ページ（`pages/article/[id].vue`）は本文の読み物部分（`.article__block`＝パンくず〜タグ）
  をひとつの`content-block`にするが、**関連商品リンク（`.article__affiliate`）とRELATED
  （`.article__related`）はこのブロックから分離する**。関連商品リンクはCMS入力の自由度が高く
  本文と地続きに見せる必要がないこと、RELATEDは別記事への導線でありまとまりとして独立させたい
  ことが理由。関連商品リンクはもともと`@include card`の白背景カードなので追加の塗りは不要、
  RELATEDには`.article__related`として`content-block`を別途持たせる
- サイドバーの「SPONSORED」（`components/SideBar.vue`）はSP/PCで見た目を統一し、常に
  `content-block`（デフォルトの`$color-bg`）として塗る（以前はPCのみカード化、SPは無地だった。
  当初`$color-card`の白背景で塗っていたが、独自の色を足さない方針に合わせて`$color-bg`に統一した）
